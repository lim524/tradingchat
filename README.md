# TradingChat · AI 트레이딩 데스크 초안

차트 없이 채팅과 계좌 상태를 중심으로 구성한 한국어 대시보드입니다. 현재 모델 API 및 Binance는 연결되지 않은 데모입니다. 실제 주문을 실행하지 않습니다.

## 기능
- 전략 관리: 채팅 → 버전별 운용안 카드 → 수정·거절·승인 → 모의 실행
- 트레이딩 데스크: 계좌·포지션·승인 상태·운용 활동을 관찰하는 전용 화면
- 전략 채팅 UI와 규칙 기반 데모 응답
- 계좌 상태, 보유 포지션, 모의 실행 및 긴급 중지
- 운용안 검토·승인 후에만 모의 실행. 설정 변경·새로고침·긴급 중지 시 재승인
- 매매 기록 및 대화 브라우저 저장, CSV 내보내기
- 전략 관리, 실행 로그, 연결 설정, 반응형 화면

## Vercel 배포
GitHub의 이 저장소를 Import합니다. Framework Preset은 Other, Build Command는 비워두고 Output Directory는 `dist`로 설정합니다. 의존성 설치나 빌드가 필요하지 않습니다. `vercel.json`에 보안 헤더와 출력 경로가 포함되어 있습니다.

로컬 확인: `python3 -m http.server 3000 --directory dist`

## 저장과 보안
현재 데이터는 해당 브라우저의 localStorage에만 저장됩니다. 브라우저 데이터를 지우면 삭제되므로 필요한 매매 기록은 CSV로 내려받으세요. 서버 저장, 사용자 인증 및 기기 간 동기화는 아직 없습니다. API 키를 입력받거나 코드에 포함하지 않습니다. 데모의 브라우저 승인은 실거래 보안 장치가 아닙니다.

## 실거래 연결 전 구현할 항목
- Vercel 서버의 사용자 인증, AI 채팅, DB 영구 저장
- PC 로컬 실행기의 Binance Futures 연동과 OS 보안 저장소
- 실행기 인증, heartbeat, 요청 만료·재전송 방지
- AI 운용안 스키마와 버전 고정, 서버/실행기의 사용자 승인 범위 검증
- 거래소 보호 주문, 중복 주문 방지, 재접속 및 주문 상태 복구
- 실현·미실현 손익, 수수료·펀딩비를 반영한 한도 감시
- 모델 ID·사용 가능 여부·가격을 공식 API에서 확인하여 환경변수로 구성

예정 구조는 고성능 모델이 채팅과 운용안을 작성하고 Flash 계열이 단기 판단을 제안하는 방식입니다. 레버리지·금액·손실 한도는 AI가 제안하고 사용자가 승인한 범위만 실행기가 허용하도록 구현해야 합니다. 현재 모의 가격과 수익은 고정 시나리오로, 수익성 검증 자료가 아닙니다.

## 채팅 데모 입력
`BTC 레버리지 3배, 증거금 10 USDT, 손실 한도 5 USDT, 최대 3회`와 같이 명시된 항목만 규칙으로 인식합니다. 미지정 수치는 이전 제안 또는 기본값을 사용하며 승인 카드에 표시합니다. 진입가·손절가 등 가격과 자유 설명은 메모만 저장하고 실행 조건으로 해석하지 않습니다. 새 제안은 승인된 설정을 즉시 변경하지 않습니다. 실행 중 또는 포지션 보유 중 새 운용안을 승인할 수 없습니다. 새로고침 후 재승인이 필요합니다.
